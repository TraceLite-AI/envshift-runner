# 先排除执行器问题

本轮有效实验固定提交 a8343672927ade57710697625273b15f604eb887，坐标协议为 normalized_0_1000。

1. 旧版提示要求截图像素，但模型输出呈现 0–1000 坐标规律。Ubuntu 初始截图为 1280×900，模型点 (200,528)，旧执行器点在按钮下方；归一化换算为 (256,475)，正落在 Choose file。Windows 为 1024×768，模型点 (175,546)，换算为 (179,419)，同样落在按钮上。旧轮只记录为接口约定不匹配，排除出任务成功率统计。
2. 修正提示，明确左上角 (0,0)、右下角 (1000,1000)，按桌面逻辑尺寸换算，并拒绝范围外坐标。轨迹记录 coordinate_mode、screen_size 和实际执行位置。修正后 Windows 的第一个点击打开了选择框，后续正确提交。
3. Windows 旧版 loop.json 使用默认编码写入中文，触发 cp1252 UnicodeEncodeError，产生半截 JSON。改为显式 UTF-8，并使控制器把损坏日志标为无效运行。这个故障发生在装置记录阶段，不算模型失败。
4. Linux 的无窗口管理器桌面不够完整，控制阶段补齐 Openbox、DBus。绝对路径键盘控制仍没有选中文件，改用真实选择框里的可见目录与文件行点击，正确文件和错误文件控制均通过。该成功路径没有暴露给模型。保留失败控制的原始证据，不声称已经确定键盘路径失效的根因。

本机仅做 Python 语法检查及坐标回归检查，没有操控用户桌面。真实截图、输入与模型调用全部在 GitHub runner 上进行。
