# G14–G16 参考来源与边界

本批是自行编写的合成 GUI 工作流。没有执行官方 benchmark 套件，也不将本批通过率与官方排行榜比较。模型只看截图、用本机键鼠操作；应用后端状态仅用于最终验收。

| 题号 | 参考的公开一手资料 | 采用的设计 | 本批实际实现 |
|---|---|---|---|
| G14 | [WorkArena++ 论文 §3、Figure 1、附录 C](https://arxiv.org/html/2407.05291v2)，[WorkArena 仓库](https://github.com/ServiceNow/WorkArena) | 将检索、计算、采购和关闭工单串成工作流；用 oracle 与状态验证器确认可完成 | 合成 Supply Desk：读库存和补货政策 → 按包装向上取整 → 一个订单 → 关联并关闭申请。不是 ServiceNow 实例。 |
| G15 | [VisualWebArena 项目](https://jykoh.com/vwa)，[官方仓库](https://github.com/web-arena-x/visualwebarena) | 目标由图像定义，完成视觉检索后的商品操作，并检查购物车真实状态 | 自绘 SVG 托特包，12 款分两页；视觉匹配后选尺寸、闭合方式和数量，保留已有商品。不是官方购物站点/图片数据集。 |
| G16 | [WebArena 官方仓库](https://github.com/web-arena-x/webarena)，[WorkArena++ 去重任务章节](https://arxiv.org/html/2407.05291v2) | 真实网站风格的多页面检索与修改；按记录关系而非按钮点击判分 | 合成 Incident Desk：核对客户、发票、故障码和创建时间，保留最早记录，批量或逐个建立 Duplicate 关系。不是官方 GitLab / ServiceNow 实例。 |

[OSWorld-Verified 的验证经验](https://xlang.ai/blog/osworld-verified)用于测试方法：等待界面初始化结束；先在三系统执行 GUI 参考路径；检查有实际修改的错误交付；允许不同操作顺序，只按题面规定的最终状态验收。

## 与旧题的关系

- G14 包含数值输入，与 G13 共享基础控件，但交付物是实际订单和申请关联；不因换了场景就宣称新的独立失败机制。
- G15 也涉及选择实体，与 G12 有基础操作重叠；新增的是视觉定义目标、跨页查找和多规格购物车。
- G16 与旧批的表格筛选/批量操作有关；新增的是多字段语义匹配和最早记录的关联约束。是否出现不同失败机制，要由实际轨迹判断。
- 三系统共用完全相同的业务规则。任何新失败先归为 GUI badcase 候选；只有进一步重复与因果排查后，才讨论稳定性或 OS 特异性。

## 已预先明确的验收

G14 必须且只能有一个订单；数量单位是“包”，不是单件；等于 Minimum 的商品不补货。G15 购物车是最终交付物，允许分两次各加一件。G16 允许批量或逐个处理，允许不同处理次序；不要求某条操作轨迹。所有题都保留原始审计与最终状态，成功后继续操作造成的最终状态错误仍按原规则计分。
